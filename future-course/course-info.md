# Course Info And Grading Expectations

Clear expectations are kind. Use this page before submitting work or preparing for a quiz.

## What This Course Prepares You To Do

By the end, you should be able to:

- read small Python programs
- write programs with choices and loops
- use functions to organize code
- work with text and lists
- save and read files
- explain your own code
- debug without panicking
- submit work with GitHub

The goal is not to memorize everything. The goal is to practice enough that new code feels less mysterious.

## Group Builds

Most Wednesday group builds are practice for Friday.

Groups change during the semester. Sometimes the instructor assigns groups, and sometimes students choose groups. One person may type while others help plan, test, explain, or debug.

Usually, group builds are not GitHub turn-ins. If asked, submit a short Canvas reflection:

1. What did your group build?
2. What did you contribute?
3. What did you learn?
4. What question do you still have?

## Quiz Expectations

Weekly quizzes are short checks, not traps.

Expect:

- about 20 minutes for most students
- 30 minutes max for slower test takers
- mostly auto-graded questions
- vocabulary, code reading, tracing, and debugging

You should be able to pass if you attend class, review the condensed slides or notes, and practice the week's code examples. Reading the textbook helps you do better, especially on code-reading questions.

## Individual Coding Projects

Most Friday projects use 20 points. Friday work is the required textbook-level assignment for the week.

| Category | Points | What It Means |
|---|---:|---|
| Program runs | 4 | It runs without crashing for normal input. |
| Required features | 6 | It does what the assignment asks. |
| Code clarity | 4 | Names, formatting, and comments help the reader. |
| Problem solving | 4 | The solution uses the week's idea reasonably. |
| Submission | 2 | Correct files are pushed and reflection is complete. |

## Group Build Feedback

Group builds are practice for Friday. They help you get ready for the required individual assignment.

| Category | Points | What It Means |
|---|---:|---|
| Participation | 3 | You contribute to coding, testing, notes, or discussion. |
| Collaboration | 3 | Your group includes people and shares work. |
| Working attempt | 2 | Your group makes a serious attempt. |
| Reflection/demo | 2 | Your group can explain what changed. |

## Stretch Work

Stretch work is part of the weekly assignment design. Try it after the required part works.

Stretch work may ask you to add:

- a harder case
- cleaner output
- an extra feature
- better input handling
- a short explanation of your design

## Released Solutions

Your instructor may release selected solutions after assignments close in Canvas.

Solutions are for review after you submit, not for completing the assignment early. Use them to ask:

- What did this solution do clearly?
- How is it similar to my code?
- How is it different from my code?
- What pattern can I reuse next time?

## Before You Submit

Check:

- I read the assignment `README.md`.
- My program runs.
- My variable names make sense.
- I completed the reflection if required.
- I pushed to GitHub.
- I refreshed GitHub and saw my latest file.

## Need Help?

Say:

- what you expected
- what happened
- the exact error message
- what you already tried
